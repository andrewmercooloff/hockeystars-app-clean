# Руководство по сборке для TestFlight

## Почему произошло расхождение между Development и Production?

### Основные причины:

1. **Разные конфигурации сборки**
   - Development build использует `expo-dev-client` с hot reload и debug-инструментами
   - Production build минифицирован, оптимизирован и не содержит debug-кода
   - Некоторые нативные модули могут работать по-разному в production

2. **Зависимости и нативные модули**
   - В development некоторые модули могут работать через Metro bundler
   - В production все нативные модули должны быть правильно скомпилированы в нативный код
   - `react-native-audio-recorder-player` требует правильной нативной интеграции

3. **Babel и Metro конфигурация**
   - Production использует оптимизированную сборку
   - Некоторые плагины могут работать по-разному
   - `react-native-reanimated` и `react-native-worklets` требуют правильной настройки

4. **Разрешения и Info.plist**
   - В production все разрешения должны быть явно указаны
   - Микрофон может не работать без правильных настроек

## Правильные шаги для сборки TestFlight

### 1. Подготовка перед сборкой

```bash
# Очистка кеша и зависимостей
rm -rf node_modules
rm -rf .expo
rm -rf ios/build
rm -rf android/build
rm -rf android/app/build

# Переустановка зависимостей
npm install

# Проверка зависимостей
npm audit
```

### 2. Проверка конфигурации

#### app.json
- ✅ Версия и build number обновлены
- ✅ Bundle identifier правильный: `by.hockeystars.app`
- ✅ Разрешения для микрофона указаны:
  ```json
  "NSMicrophoneUsageDescription": "This app uses microphone to measure puck speed..."
  ```
- ✅ Плагин expo-av настроен:
  ```json
  ["expo-av", {
    "microphonePermission": "This app uses microphone..."
  }]
  ```

#### eas.json
- ✅ Production профиль настроен
- ✅ `autoIncrement: true` для автоматического увеличения build number

#### package.json
- ✅ Все зависимости актуальны
- ✅ `react-native-audio-recorder-player: ^4.5.0` присутствует
- ✅ `expo-av: ~16.0.7` присутствует

### 3. Проверка нативных модулей

#### Для react-native-audio-recorder-player:
- Модуль должен быть правильно установлен в нативный код
- Проверь, что в `ios/Podfile` есть зависимость
- После изменений в нативных модулях нужно пересобрать

### 4. Локальная проверка перед сборкой

```bash
# Запуск в development режиме для проверки
npm start

# Проверка на реальном устройстве
# Убедись, что:
# - Главная страница работает без ошибок
# - Аудио-радар работает (микрофон включается, пики двигаются)
# - Все функции работают корректно
```

### 5. Сборка для TestFlight

#### Вариант 1: Через EAS Build (рекомендуется)

```bash
# Убедись, что EAS CLI установлен
npm install -g eas-cli

# Логин в EAS
eas login

# Сборка production версии для iOS
eas build --platform ios --profile production

# После успешной сборки загрузи в App Store Connect
eas submit --platform ios --profile production
```

#### Вариант 2: Через Xcode (альтернатива)

```bash
# Генерация нативного проекта
npx expo prebuild --platform ios

# Открой в Xcode
open ios/HockeyStars.xcworkspace

# В Xcode:
# 1. Выбери правильный Team и Provisioning Profile
# 2. Product → Archive
# 3. Distribute App → App Store Connect
```

### 6. После сборки - проверка

1. **Загрузи билд в App Store Connect**
2. **Дождись обработки** (обычно 10-30 минут)
3. **Проверь в TestFlight:**
   - Установи на реальное устройство
   - Проверь главную страницу
   - Проверь аудио-радар (микрофон, пики, детекция звука)
   - Проверь все основные функции

## Решение проблем с аудио-радаром в Production

### Проблема: Микрофон включается, но пики не двигаются

#### Возможные причины:

1. **react-native-audio-recorder-player не работает в production**
   - Модуль может требовать дополнительной настройки
   - Проверь, что нативный код правильно скомпилирован

2. **expo-av метринг не работает**
   - В production может быть другой путь к метрике
   - Проверь логи в TestFlight

3. **Разрешения не применены**
   - Убедись, что `NSMicrophoneUsageDescription` присутствует
   - Проверь, что пользователь дал разрешение

#### Решения:

1. **Проверь логи в TestFlight:**
   - Включи логирование в коде
   - Используй `console.log` для отладки
   - Проверь, что логи видны в TestFlight

2. **Проверь инициализацию AudioRecorderPlayer:**
   ```typescript
   // В app/puck-speed-sound.tsx
   // Убедись, что инициализация работает в production
   // Добавь больше логов для отладки
   ```

3. **Альтернатива: Используй только expo-av**
   - Если react-native-audio-recorder-player не работает
   - Используй expo-av для всех платформ
   - Это более стабильное решение для production

4. **Проверь нативные зависимости:**
   ```bash
   cd ios
   pod install
   cd ..
   ```

## Важные замечания

1. **Всегда тестируй локально перед сборкой**
   - Development build должен работать идеально
   - Если что-то не работает в development, не будет работать и в production

2. **Используй одинаковые версии зависимостей**
   - Не обновляй зависимости перед production сборкой
   - Если обновил - протестируй тщательно

3. **Проверяй логи**
   - В production логи могут быть минифицированы
   - Используй явные console.log для отладки

4. **Нативные модули требуют пересборки**
   - После изменений в нативных модулях нужна полная пересборка
   - Не используй кешированные билды

## Следующие шаги для исправления текущей проблемы

1. **Проверь логи в TestFlight** - что именно не работает
2. **Сравни зависимости** - development vs production
3. **Проверь нативную интеграцию** react-native-audio-recorder-player
4. **Рассмотри использование только expo-av** для стабильности
5. **Собери новую версию** с исправлениями

## Конкретные исправления для текущих проблем

### Проблема 1: Главная страница с ошибками в TestFlight

**Причина:** Разные зависимости или конфигурация между development и production

**Решение:**
1. Проверь, что все зависимости одинаковые:
   ```bash
   npm install --legacy-peer-deps
   ```
2. Убедись, что нет конфликтов версий в package.json
3. Проверь, что все импорты корректны
4. Убедись, что нет условных импортов, которые могут не работать в production

### Проблема 2: Аудио-радар не работает в TestFlight

**Причина:** 
- `react-native-audio-recorder-player` может не работать правильно в production сборке
- Expo-av метринг может требовать дополнительной настройки
- Нативные модули могут не быть правильно скомпилированы

**Решение:**

#### Вариант A: Исправить react-native-audio-recorder-player

1. **Проверь нативную интеграцию:**
   ```bash
   cd ios
   pod install
   cd ..
   ```

2. **Убедись, что модуль правильно импортирован:**
   - В production может потребоваться другой способ импорта
   - Проверь, что все пути к модулю правильные

3. **Добавь fallback на expo-av:**
   - Если react-native-audio-recorder-player не работает, используй expo-av
   - Это более стабильное решение для production

#### Вариант B: Использовать только expo-av (рекомендуется)

1. **Убери зависимость от react-native-audio-recorder-player**
2. **Используй только expo-av для всех платформ**
3. **Проверь, что expo-av правильно настроен в app.json:**
   ```json
   ["expo-av", {
     "microphonePermission": "This app uses microphone..."
   }]
   ```

4. **Убедись, что метринг включен:**
   - В expo-av метринг должен быть включен при создании записи
   - Проверь, что `getStatusAsync()` возвращает метринг

#### Вариант C: Добавить больше логирования

1. **Добавь логи для отладки в production:**
   ```typescript
   console.log('[AUDIO] Инициализация начата');
   console.log('[AUDIO] Разрешения:', hasPermission);
   console.log('[AUDIO] Платформа:', Platform.OS);
   ```

2. **Проверь логи в TestFlight:**
   - Используй Xcode Console или TestFlight logs
   - Ищи ошибки инициализации

3. **Добавь обработку ошибок:**
   ```typescript
   try {
     // код инициализации
   } catch (error) {
     console.error('[AUDIO] Ошибка:', error);
     // fallback на expo-av
   }
   ```

### Проблема 3: Пики не двигаются

**Причина:** 
- Метринг не обновляется
- Интервал опроса не работает
- Амплитуда не рассчитывается

**Решение:**

1. **Проверь, что интервал работает:**
   ```typescript
   // Убедись, что setInterval вызывается
   console.log('[AUDIO] Интервал установлен');
   ```

2. **Проверь, что метринг возвращает данные:**
   ```typescript
   const status = await recording.getStatusAsync();
   console.log('[AUDIO] Метринг:', status.metering);
   ```

3. **Проверь, что амплитуда обновляется:**
   ```typescript
   setCurrentAmplitude(amplitude);
   console.log('[AUDIO] Амплитуда обновлена:', amplitude);
   ```

## Рекомендуемый план действий

1. **Сначала:** Проверь логи в TestFlight, чтобы понять точную проблему
2. **Затем:** Исправь зависимости и конфигурацию
3. **Потом:** Рассмотри переход на expo-av только (более стабильно)
4. **Наконец:** Собери новую версию и протестируй
