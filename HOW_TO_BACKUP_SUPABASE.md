# Как создать резервную копию базы данных в Supabase

## ⚠️ Важно: В Supabase резервные копии создаются автоматически!

В Supabase **нельзя создать резервную копию вручную** через интерфейс. Резервные копии создаются автоматически каждый день около полуночи (по времени региона вашего проекта).

## Способ 1: Использовать последнюю автоматическую резервную копию (Самый простой)

### Шаг 1: Проверьте существующие резервные копии
1. Откройте Supabase Dashboard: https://supabase.com/dashboard
2. Выберите ваш проект
3. Перейдите в **Database** → **Backups**
4. На вкладке **"Scheduled backups"** вы увидите список автоматических резервных копий

### Шаг 2: Используйте последнюю резервную копию
- Последняя резервная копия (самая верхняя в списке) - это ваша текущая точка восстановления
- Если что-то пойдет не так, вы сможете восстановиться из этой резервной копии через кнопку **"Restore"**

### Шаг 3: Выполните скрипт
- Скрипт `fix_performance_rls_policies.sql` безопасен - он использует `DROP ... IF EXISTS`, поэтому не вызовет ошибок
- Если что-то пойдет не так, вы всегда сможете восстановиться из автоматической резервной копии

## Способ 2: Через SQL (pg_dump) - для локальной копии

Если у вас есть доступ к базе данных через командную строку:

### Шаг 1: Получите данные подключения
1. В Supabase Dashboard перейдите в **Settings** → **Database**
2. Найдите раздел **"Connection string"** или **"Connection pooling"**
3. Скопируйте строку подключения (URI или параметры)

### Шаг 2: Установите PostgreSQL клиент (если не установлен)
- **Windows:** Скачайте PostgreSQL с https://www.postgresql.org/download/windows/
- **macOS:** `brew install postgresql`
- **Linux:** `sudo apt-get install postgresql-client` (Ubuntu/Debian)

### Шаг 3: Создайте резервную копию
```bash
# Используя строку подключения
pg_dump "postgresql://postgres:[PASSWORD]@[HOST]:5432/postgres" > backup.sql

# Или с параметрами
pg_dump -h [HOST] -U postgres -d postgres -F c -f backup.dump
```

**Пример:**
```bash
pg_dump "postgresql://postgres.abcdefghijklmnop:[PASSWORD]@aws-0-us-east-1.pooler.supabase.com:6543/postgres" > backup_$(date +%Y%m%d_%H%M%S).sql
```

## Способ 3: Через Supabase CLI (для разработчиков)

### Шаг 1: Установите Supabase CLI
```bash
npm install -g supabase
```

### Шаг 2: Войдите в Supabase
```bash
supabase login
```

### Шаг 3: Создайте резервную копию
```bash
# Создать резервную копию через CLI
supabase db dump -f backup.sql
```

## Восстановление из резервной копии

### Если создали через Dashboard:
1. Перейдите в **Database** → **Backups**
2. Найдите нужную резервную копию
3. Нажмите **"Restore"** или **"Restore to..."**
4. Подтвердите восстановление

⚠️ **Внимание:** Восстановление перезапишет текущую базу данных!

### Если создали через pg_dump:
```bash
# Восстановление из SQL файла
psql "postgresql://postgres:[PASSWORD]@[HOST]:5432/postgres" < backup.sql

# Или из dump файла
pg_restore -h [HOST] -U postgres -d postgres backup.dump
```

---

## Рекомендации

1. **Регулярные резервные копии:** Создавайте резервные копии перед важными изменениями
2. **Названия:** Используйте понятные названия с датой: `backup-2024-01-15-performance-fix`
3. **Хранение:** Сохраняйте несколько последних резервных копий
4. **Проверка:** Всегда проверяйте, что резервная копия успешно создана перед выполнением скриптов

## Быстрая ссылка

После входа в Supabase Dashboard, перейдите напрямую:
```
https://supabase.com/dashboard/project/[ваш-project-id]/database/backups
```

Замените `[ваш-project-id]` на ID вашего проекта (можно найти в URL или в настройках проекта).
