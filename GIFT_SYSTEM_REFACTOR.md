# Рефакторинг системы подарков

## 📋 Обзор изменений

Система подарков была полностью переработана для улучшения пользовательского опыта и производительности.

## 🎯 Основные изменения

### 1. Новый процесс запроса подарков

**Было:**
- Игрок запрашивает конкретный тип подарка (клюшка, шайба, джерси, автограф)
- Звезда видит кнопки "Принять" и "Отказать"
- При принятии автоматически отправляется подарок из инвентаря звезды

**Стало:**
- Игрок может запросить конкретный тип ИЛИ любой подарок (кнопка "Попросить подарок")
- Звезда видит только кнопку "Подарить"
- При нажатии "Подарить" звезда переходит на профиль игрока в раздел музей
- Звезда выбирает подарок из своего инвентаря ИЛИ создает новый

### 2. Множественное использование подарков

**Было:**
- Каждый подарок имел флаг `is_available`
- После отправки подарок становился недоступным
- Подарки копировались для каждого получателя

**Стало:**
- Убран флаг `is_available`
- Подарки остаются в инвентаре звезды/админа
- Используются ссылки на изображения (не копируются)
- Один подарок может быть у многих игроков

### 3. Кнопка "Отправить подарок"

**Было:**
- Кнопка видна только админу в режиме редактирования

**Стало:**
- Кнопка видна всегда для звезд и админов
- Звезды и админы могут отправить подарок в любой момент
- Разные модальные окна для звезд (`StarGiftModal`) и админов (`AdminGiftModal`)

## 🗄️ Изменения в базе данных

### Миграция: `update_gift_system.sql`

```sql
-- Удаляем колонку is_available
ALTER TABLE items DROP COLUMN IF EXISTS is_available;

-- Добавляем колонку для кастомного названия подарка
ALTER TABLE player_museum ADD COLUMN IF NOT EXISTS custom_name VARCHAR(255);

-- Добавляем колонку для отслеживания статуса запроса
ALTER TABLE item_requests ADD COLUMN IF NOT EXISTS gift_sent_at TIMESTAMP WITH TIME ZONE;
```

### Новые типы данных

```typescript
// Добавлен тип 'custom' для подарков
item_type: 'autograph' | 'stick' | 'puck' | 'jersey' | 'custom'

// Новое поле в player_museum
custom_name?: string; // Кастомное название подарка

// Новое поле в item_requests
gift_sent_at?: string; // Время отправки подарка
```

## 🎮 Пользовательский сценарий

### Для игрока:
1. Открывает профиль звезды
2. Видит кнопки запроса подарков
3. Нажимает "Попросить подарок" (или конкретный тип)
4. Пишет сообщение с просьбой
5. Получает уведомление о получении подарка

### Для звезды:
1. Получает уведомление о запросе подарка
2. Видит кнопку "Подарить"
3. Нажимает "Подарить" → переход на профиль игрока
4. Автоматическая прокрутка к разделу "Музей"
5. Нажимает кнопку "Отправить подарок" под музеем
6. Выбирает подарок из своего инвентаря ИЛИ создает новый
7. Отправляет подарок

### Для админа:
1. Открывает профиль любого игрока
2. Видит кнопку "Отправить подарок" под музеем (всегда)
3. Нажимает кнопку
4. Выбирает подарок из инвентаря ИЛИ создает новый
5. Отправляет подарок

## 🚀 Преимущества новой системы

### Производительность:
- ✅ Подарки не копируются (используются ссылки)
- ✅ Меньше запросов к базе данных
- ✅ Быстрая загрузка музея

### Гибкость:
- ✅ Звезды могут создавать уникальные подарки
- ✅ Кастомные названия для каждого получателя
- ✅ Поддержка PNG с прозрачностью

### Удобство:
- ✅ Простой интерфейс выбора подарков
- ✅ Визуальный предпросмотр всех подарков
- ✅ Автоматическая прокрутка к музею

### Масштабируемость:
- ✅ Один подарок может быть у многих игроков
- ✅ Не нужно хранить копии изображений
- ✅ Легко добавлять новые типы подарков

## 🔧 Техническая реализация

### Кеширование:
- Сохранена система кеширования для быстрой работы
- Кеш очищается при отправке подарка
- Используется `AsyncStorage` для хранения кеша

### Уведомления:
- Игрок получает уведомление о получении подарка
- Друзья игрока получают уведомления
- Обновляется счетчик уведомлений

### Изображения:
- Поддержка PNG с прозрачностью
- Загрузка в хранилище Supabase (`avatars` bucket)
- Автоматическое определение типа контента
