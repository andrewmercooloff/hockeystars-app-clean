# Исправление дублирующихся push-уведомлений

## Проблема
Пользователи получали множественные дублирующиеся push-уведомления при изменении данных друзей. Это происходило из-за нескольких источников дублирования в системе.

## Найденные источники дублирования

### 1. Множественные Realtime подписки
- В `_layout.tsx` создавалась дополнительная подписка на счетчик сообщений
- В `messages.tsx` создавалась дублирующаяся подписка на сообщения
- RealtimeManager уже содержал эти подписки

### 2. Неэффективное кеширование
- Кеш уведомлений в `notificationService.ts` был слишком коротким (5 секунд)
- Ключи кеширования не учитывали все параметры уведомления
- Отсутствовала проверка на дублирование в `playerStorage.ts`

### 3. Каскадные обновления
- При каждом изменении счетчика вызывался `loadUser()`
- Это могло приводить к повторным обновлениям и новым уведомлениям

## Внесенные исправления

### 1. Централизация Realtime подписок
**Файл: `utils/RealtimeManager.ts`**
- Добавлена подписка на счетчик сообщений в RealtimeManager
- Добавлен callback для обновления счетчика сообщений
- Улучшено логирование для отслеживания подписок

**Файл: `app/_layout.tsx`**
- Удалена дублирующаяся подписка на счетчик сообщений
- Используется централизованный RealtimeManager для всех подписок
- Добавлен callback для счетчика сообщений

**Файл: `app/messages.tsx`**
- Переименована подписка на сообщения для избежания конфликтов
- Добавлено логирование для различения UI обновлений и push уведомлений

### 2. Улучшение системы кеширования
**Файл: `utils/notificationService.ts`**
- Увеличен период кеширования с 5 до 10 секунд
- Улучшен ключ кеширования с включением данных уведомления
- Добавлено более детальное логирование

**Файл: `utils/playerStorage.ts`**
- Улучшена система предотвращения дублирования push уведомлений
- Добавлена двойная проверка (локальный + глобальный кеш)
- Увеличен период кеширования до 5 минут

### 3. SQL скрипты для очистки
**Файл: `clean_duplicate_notifications.sql`**
- Улучшен скрипт для очистки существующих дублирующихся уведомлений
- Добавлена статистика до и после очистки
- Добавлен анализ дублирующихся уведомлений

**Файл: `monitor_duplicate_notifications.sql`**
- Создан скрипт для мониторинга дублирующихся уведомлений в реальном времени
- Добавлена статистика по часам и пользователям
- Проверка на дублирующиеся push токены

## Результат

### Ожидаемые улучшения:
1. **Устранение дублирования**: Пользователи больше не будут получать множественные одинаковые уведомления
2. **Улучшение производительности**: Меньше ненужных Realtime подписок и обновлений
3. **Лучший мониторинг**: Возможность отслеживать и предотвращать дублирование

### Логи для отслеживания:
- `⏭️ Realtime подписки уже настроены для пользователя` - предотвращение повторных подписок
- `⏭️ Пропускаем дублирующееся push-уведомление` - предотвращение дублирования
- `🔔 Пропускаем дублирующееся уведомление` - кеширование в notificationService

## Тестирование

### Для проверки исправлений:
1. Запустить SQL скрипт `monitor_duplicate_notifications.sql` для анализа текущего состояния
2. Выполнить `clean_duplicate_notifications.sql` для очистки существующих дубликатов
3. Протестировать отправку уведомлений при изменении данных друзей
4. Проверить логи на наличие сообщений о предотвращении дублирования

### Критерии успеха:
- Отсутствие дублирующихся уведомлений в логах
- Снижение количества уведомлений в базе данных
- Отсутствие жалоб пользователей на множественные уведомления

## Дополнительные рекомендации

1. **Мониторинг**: Регулярно запускать `monitor_duplicate_notifications.sql` для отслеживания
2. **Алерты**: Настроить алерты при обнаружении большого количества дублирующихся уведомлений
3. **Тестирование**: Добавить unit-тесты для проверки логики предотвращения дублирования
4. **Документация**: Обновить документацию по системе уведомлений
