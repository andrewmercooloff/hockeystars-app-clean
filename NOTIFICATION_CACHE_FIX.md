# Исправление логики кеширования уведомлений

## 🐛 **Проблема**
Система блокировала **разные изменения статистики** (1→2, затем 2→3), считая их дубликатами.

### Логи показывали:
```
⏭️ Пропускаем дубликат уведомления для пользователя
⏭️ Пропускаем дублирующееся push-уведомление (глобальный кеш)
```

## ✅ **Исправления**

### 1. **Улучшена логика дедупликации уведомлений**
**Было:** Блокировались все уведомления от одного игрока за 5 минут
**Стало:** Блокируются только уведомления с **теми же изменениями** за 30 секунд

```typescript
// Сравниваем конкретные изменения, а не просто игрока
return existingData?.changedPlayerId === playerId && 
       JSON.stringify(existingData?.changes) === JSON.stringify(currentData?.changes);
```

### 2. **Улучшена логика кеширования push-уведомлений**
**Было:** Кеш по `userId_playerId_type`
**Стало:** Кеш по `userId_playerId_type_changesHash`

```typescript
const changesHash = JSON.stringify(userNotifications[0]?.data?.changes || []);
const pushCacheKey = `${userId}_${playerId}_${notificationType}_${changesHash}`;
```

### 3. **Уменьшено время кеширования**
- **Основной кеш**: 1 минута → **30 секунд**
- **Push кеш**: 1 минута → **30 секунд**
- **Дедупликация**: 5 минут → **30 секунд**

## 🎯 **Результат**

### Теперь система:
- ✅ **Разрешает разные изменения** (1→2, затем 2→3)
- ✅ **Блокирует только точные дубликаты** (1→2, затем снова 1→2)
- ✅ **Быстрее реагирует** на новые изменения (30 секунд вместо 5 минут)
- ✅ **Сохраняет защиту** от спама и дублирования

### Логи для отслеживания:
- `⏭️ Пропускаем дубликат уведомления с теми же изменениями` - правильная блокировка
- `📢 Отправлено X уведомлений о статистике` - уведомления отправлены
- `✅ Уведомления отправлены на X/Y устройств` - push доставлены

## 🧪 **Тестирование**

1. **Измените статистику** (например, голы: 1→2)
2. **Подождите 30 секунд**
3. **Измените статистику снова** (голы: 2→3)
4. **Проверьте уведомления** - они должны прийти!

Теперь система работает корректно и не блокирует разные изменения! 🚀
