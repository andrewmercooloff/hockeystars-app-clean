# Исправление RLS политик для push_tokens

## Проблема
Ошибка: `"new row violates row-level security policy for table \"push_tokens\""`

Эта ошибка возникает из-за:
1. Конфликтующих RLS политик (несколько политик для одной операции)
2. Возможных проблем с NULL в `auth.uid()` при проверке политик
3. Неправильного сравнения типов (user_id - TEXT, auth.uid() - UUID)

## Решение

### Шаг 1: Выполните исправленный скрипт

Откройте Supabase Dashboard → SQL Editor и выполните скрипт:
```
database/fix_push_tokens_rls.sql
```

Этот скрипт:
- Удаляет все существующие конфликтующие политики
- Создает новые политики с правильными проверками на NULL
- Использует правильное сравнение типов (TEXT с UUID)

### Шаг 2: (Опционально) Диагностика

Если проблема сохраняется, выполните диагностический скрипт:
```
database/diagnose_push_tokens_rls.sql
```

Этот скрипт покажет:
- Все текущие политики для `push_tokens`
- Состояние RLS (включен/выключен)
- Структуру таблицы
- Текущего пользователя (если выполняется от имени аутентифицированного пользователя)

### Шаг 3: Проверка

После выполнения скрипта:
1. Перезапустите приложение
2. Попробуйте зарегистрировать push token
3. Проверьте логи - ошибка должна исчезнуть

## Что изменилось

### Старые политики (проблемные):
- Не проверяли `auth.uid() IS NOT NULL`
- Могли конфликтовать друг с другом
- Использовали неправильное сравнение типов

### Новые политики (исправленные):
- ✅ Проверяют `auth.uid() IS NOT NULL` перед сравнением
- ✅ Используют правильное сравнение `(select auth.uid())::text = user_id`
- ✅ Удалены все конфликтующие политики перед созданием новых

## Важные замечания

1. **Политики работают только для аутентифицированных пользователей** (`TO authenticated`)
2. **Проверка на NULL обязательна** - если `auth.uid()` NULL, политика блокирует операцию
3. **Типы данных**: `user_id` - TEXT, `auth.uid()` - UUID, поэтому используется приведение типов `::text`

## Если проблема сохраняется

1. Проверьте, что пользователь действительно аутентифицирован в момент вставки токена
2. Убедитесь, что `user_id` в токене совпадает с `auth.uid()` пользователя
3. Выполните диагностический скрипт и проверьте результаты
4. Проверьте логи Supabase на наличие других ошибок
