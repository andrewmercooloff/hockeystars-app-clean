# Changelog для TestFlight v1.0.2

## Исправления

### 1. Проблема с вылетом шайб за границы
**Проблема:** В TestFlight шайбы вылетали за правую и нижнюю границы экрана, хотя в development build все работало.

**Причина:** Версии зависимостей с символами `^` и `~` обновлялись в production, что приводило к несовместимости.

**Решение:**
- Зафиксированы точные версии критичных зависимостей:
  - `react-native-reanimated: 4.1.4` (было `^4.1.4`)
  - `react-native-worklets-core: 1.6.2` (было `^1.6.2`)
  - `react-native-gesture-handler: 2.28.0` (было `~2.28.0`)

### 2. Проблема с аудио-радаром в TestFlight
**Проблема:** В TestFlight микрофон включался, но пики громкости не двигались и звук не определялся.

**Причина:** `react-native-audio-recorder-player` может не работать правильно в production сборке. Callback `addRecordBackListener` может не вызываться.

**Решение:**
- Добавлен автоматический fallback на `expo-av`
- Если callback не вызывается в течение 3 секунд, система автоматически переключается на `expo-av`
- Используется polling метеринга через `getStatusAsync()` каждые 100ms
- Полная совместимость с существующей логикой детекции звука

**Как это работает:**
1. Система пытается использовать `react-native-audio-recorder-player` (как раньше)
2. Если callback не вызывается в течение 3 секунд → автоматический переход на `expo-av`
3. Если `AudioRecorderPlayer` не инициализирован → сразу используется `expo-av`
4. Если возникает ошибка при запуске → fallback на `expo-av`

## Технические детали

### Fallback на expo-av
- Функция `startExpoAVRecording()` создает запись через `Audio.Recording.createAsync()`
- Метеринг опрашивается через `setInterval` каждые 100ms
- Данные метеринга преобразуются в тот же формат, что и `AudioRecorderPlayer`
- Используется та же логика детекции звука (пороги, скачки амплитуды)

### Зафиксированные версии
Все критичные зависимости теперь имеют точные версии без символов обновления (`^`, `~`), что гарантирует одинаковое поведение в development и production.
